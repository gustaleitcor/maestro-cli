Maestro

maestro.toml keys

maestro.toml sits at the root of the repository. The file and every key in it are optional. maestro.toml: how the image is run introduces the keys one at a time, and this page is the lookup table.

The keys

KeyTypeDefaultWhat it sets
parametersList of stringsOne line that runs the image's own CMDThe lines of a run. Each string becomes the arguments of one container.
generatorStringNoneA Python script in the repository whose genvrs function yields more lines
outputsList of stringsNone, so only the logs are keptThe files and directories to keep from each container
outputs_layout"per-line" or "shared""per-line"Whether each line's outputs go in a directory of their own or all into one tree for the run
outputs_everyDuration, such as "30m"None, so outputs are copied only when a line endsHow often a running line's logs and outputs are copied out
cpusWhole number1The cores each container can use, and the cores a machine must have free to start it
memoryWhole number, in MB512The memory each container can use, and the memory a machine must have free to start it
envTable of stringsNoneEnvironment variables set in every container
retriesWhole number0How many times a line that loses its machine goes back to the queue
timeDuration, such as "90m" or "2h"The server's limit, a week unless your administrator set anotherThe longest each line may run before Maestro stops it
machinesList of stringsAny machineThe only machines the lines can run on
dockerfileStringContainerfile at the root, or else DockerfileThe file the image is built from

A path in outputsA file or directory inside the container. It can't be / or the working directory itself, and it can't begin with ...

Maestro also refuses a run when one of its lines asks for more cpus or memory than any machine it may use has for lines, even with nothing else running there.

How a line is split into words

Maestro splits each line of parameters, and each string a generator yields, at spaces and tabs. No shell is involved.

WrittenMeaning
'two words'One argument. Everything inside single quotes is taken as written.
"two words"One argument. Inside double quotes, a backslash keeps the next character as written, so \" is a quote.
two\ wordsOne argument. A backslash keeps the next character as written.
$HOME, *, ~Passed to the program as typed, because no shell expands them

A line with a quote left open, or one that ends in a backslash, is an error.

Per-line settings from a generator

A generator's Config class can set outputs, cpus, memory, env, time and retries for the lines it yields, within the same limits. Lines that need different settings shows how.

A file with every key

parameters = [
  "--seed 1 results/",
  "--seed 2 results/",
]
generator      = "genvrs.py"
outputs        = ["results/", "summary.json"]
outputs_layout = "per-line"
outputs_every  = "30m"
cpus           = 4
memory         = 8192
env            = { MODE = "fast" }
time           = "2h"
retries        = 2
machines       = ["Q1", "Q2"]
dockerfile     = "docker/Dockerfile"

Errors

An unknown key fails the build and lists the keys Maestro knows:

maestro.toml: unknown key "paramters" (known: machines, parameters, generator, dockerfile, outputs, outputs_layout, outputs_every, cpus, memory, env, time, retries)

The other messages name the key and the value at fault, as these do:

maestro.toml: cpus is 0; give between 1 and 1024 cores
maestro.toml: memory is 4; give between 6 and 16777216 MB
maestro.toml: retries is 9; give between 0 and 5
maestro.toml: time "2 hours" isn't a duration; give one such as "90m" or "2h"
maestro.toml: outputs_layout "merged" must be "per-line" (each line's outputs apart, the default) or "shared" (every line's in one tree)
