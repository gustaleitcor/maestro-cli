Maestro

Glossary

maestro help concepts prints a short version of this page in the terminal.

The things you work with

WordMeaningMore
RepoA git repository of yours on GitHub, GitLab, Codeberg, or another Forgejo or Gitea server. It holds your program and a Dockerfile, and usually a maestro.toml that says how to run the image.Your own copy of the template
ForgeThe place a repository lives, as Maestro reaches it: the forge's API and a read-only token of yours. The CLI keeps the token and sends it to the server when the server needs to clone. A forge never signs anyone in.Git forges
BuildThe result of maestro build <repo>, which clones a repository at one commit and builds a container image from it. A build has a number, written #12. The build also reads maestro.toml and computes the lines, so every run of a build has the same lines.Builds and images
ImageWhat a build makes: your program and everything it needs, ready to start as a container. You keep 10 at a time unless your administrator set another number. When a new build needs room, the image you ran least recently is removed.How many images you keep
RunThe result of maestro run <build>, which runs a build's image on the machines. A run has a number of its own, written run 31. Build numbers and run numbers count separately.Runs and lines
LineOne container of a run. maestro.toml lists lines of parameters and can name a generator that computes more. A run starts one container for each line, with the line's words in place of the image's CMD. Without a maestro.toml, a run is one line that runs the image's own command. A run has at most 1000 lines.parameters
GeneratorA Python script in the repository whose genvrs function yields lines.Generating lines with Python
OutputsThe files maestro.toml names, copied out of each container when it ends. They are kept beside what the container printed, stdout.log and stderr.log. maestro runs get downloads all of it.What a line leaves behind
MachineA computer whose Podman runs the containers. Maestro reaches it over SSH. A line runs on one machine, the first allowed one that has room for its cores and memory.Watching the machines
GroupA set of users. Groups take turns at the machines, so a lab of ten doesn't crowd out a lab of two. Everyone is in one group until an administrator makes more.Groups

The statuses of a line

A line waits at three levels before it runs.

StatusThe line is
queuedWaiting to be chosen from among its user's lines
stagedChosen, and waiting for a machine
assignedGiven to a machine, and waiting for room on it while its image is copied there
starting, runningIn a container on the machine

It then ends in one of four ways.

StatusWhat happened
succeededThe program exited with 0.
failedThe program exited with another code.
errorThe line couldn't run, for a reason on Maestro's side and outside your program.
cancelledIts run was cancelled before it ended.

The queue explains the waiting levels, and How a line ends the endings.

The programs

NameWhat it is
orqThe server. It builds images, schedules lines and keeps every record.
viewThe Maestro page in your browser
CLIThe maestro command

The parts shows how they connect.

The scheduler's words

WordMeaning
PolicyThe rule that makes one of the scheduler's four choices, such as fifo or pq
ScoreThe number pq ranks lines by, built from a line's cores, memory and waiting time and its user's share
ShareHow much of the machines a user holds or has used, as the chosen measure counts it

Policies and the score defines all three.
